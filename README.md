# 投稿審查系統

依據「1151 期中個人專題」簡報製作的繁體中文投稿審查網頁，介面名稱為「稿間」。作者可管理投稿，編輯可通過或退回稿件。

## 目前進度

v0.1 已完成可操作的瀏覽器示範版，介面採用深色模式及加大字體，使用 HTML、CSS 與原生 JavaScript，無第三方套件依賴。

## 本機執行

安裝 Node.js 20 或更新版本，在專案資料夾執行：

```sh
npm start
```

開啟 http://127.0.0.1:4173 。不需要執行 npm install。停止時在終端機按 Ctrl+C。

也可直接用瀏覽器開啟 `web/index.html`，但建議使用上述 HTTP 伺服器，以獲得較一致的本機儲存行為。

## 功能

- 登入頁提供兩位作者與一位編輯的示範帳號，登入後顯示目前身分與登出按鈕。
- 作者查看自己的稿件，新增、修改、刪除編輯中稿件，以及送出投稿。
- 編輯查看審查中稿件的作者、類別、標題與完整內容，選擇通過或填寫原因後退回，作者可在內容與編輯頁查看退回原因。
- 三種狀態的轉換限制、必填及空白驗證、刪除與送出確認。
- 狀態篩選、標題／類別搜尋、稿件統計、空結果提示。
- 響應式排版、鍵盤操作、未儲存修改的離開確認。
- 使用 localStorage 保存稿件，重新整理後保留，其他同來源分頁會同步顯示更新。

## 示範方式

1. 在登入頁選「奶龍」，按登入工作空間，新增一篇稿件並儲存後送出。
2. 登出後使用「自由時報」登入，開啟該稿件，填寫退回原因後確認退回。
3. 登出並以原作者登入，查看上次退回原因，修改稿件並再次送出。
4. 登出並以編輯登入，選擇通過。
5. 登出並以作者登入，確認稿件顯示已通過，且只提供查看。

首次開啟自動建立五篇虛構範例稿件，涵蓋兩位作者與三種狀態。範例內容僅供操作展示。

## 測試與建置

```sh
npm test
npm run build
```

自動測試涵蓋完整投稿流程、作者所有權、角色及狀態限制、刪除、欄位驗證與資料格式檢查。靜態建置輸出至 `dist/`，可交給靜態網站服務部署。

## 初版限制

這是前端流程展示，登入頁僅為前端示範驗證，不是正式帳號登入服務，資料只存在目前瀏覽器與網站來源中。不同電腦、瀏覽器或網站網址的資料不會共用；清除網站資料會移除稿件。若要恢復範例，可在瀏覽器開發工具刪除 localStorage 的 `manuscript-studio:v1` 後重新整理，原有稿件會遺失。

目前沒有後端、帳號驗證與共用資料庫。前端的角色限制不具備真正的安全隔離能力；正式多人版需另加伺服器身分與權限檢查。儲存或讀取失敗時顯示提示，且不會靜默覆寫已損壞的資料。多分頁同時編輯同一篇草稿時，以最後成功儲存的內容為準。

## 程式結構

- `web/index.html`：網頁骨架。
- `web/styles.css`：桌面與手機排版。
- `web/core.js`：身分、資料驗證與稿件狀態規則。
- `web/app.js`：畫面、表單、確認視窗與本機儲存。
- `scripts/`：本機伺服器與靜態建置腳本。
- `tests/`：Node.js 內建測試工具撰寫的核心流程測試。

## 核心流程

作者新增稿件 → 編輯中 → 送出投稿 → 審查中。

編輯審查：通過 → 已通過；退回 → 編輯中 → 作者修改並再次送出。

## 需求來源與界線

來源：使用者提供的「1151 期中個人專題.pptx」第 1 頁。

文件明確區分簡報原始要求與實作建議。七天時程為規劃假設，並非老師指定期限。原始簡報不包含在本專案內。
