# 需求規格

## 一、簡報原始要求

系統名稱：投稿審查。兩種角色：作者、編輯。

### 作者功能

- 查看投稿稿件清單，顯示類別、標題、審查狀態。
- 新增及編輯投稿，欄位包含類別、標題、文章內容；狀態為編輯中。
- 刪除編輯中稿件。
- 送出投稿，將編輯中改為審查中。

### 編輯功能

- 查看待審查清單，顯示作者、類別、標題。
- 查看稿件內容。
- 選擇通過，將審查中改為已通過。
- 退回稿件，將審查中改為編輯中。

### 稿件狀態

1. 編輯中。
2. 審查中。
3. 已通過。

## 二、建議採用的操作規則

以下屬於實作建議，並非全部由簡報明文規定。

- 作者只可查看及操作自己的稿件。
- 只有編輯中稿件可以修改、刪除或送出。
- 編輯只能審查審查中稿件。
- 已通過稿件保留供查看。
- 類別、標題與文章內容皆必填；只有空白字元視為未填。
- 刪除前須確認；取消時保留稿件。
- 退回稿件可修改並重新送出。
- 操作完成後清單與詳細頁應反映最新狀態。
- 若採前後端架構，後端應獨立檢查身分、所有權與狀態，不能只靠畫面按鈕限制。

## 三、建議畫面

1. 作者投稿清單：類別、標題、狀態，以及依狀態提供的操作。
2. 新增／編輯稿件頁：共用表單，包含類別、標題、文章內容。
3. 編輯待審查清單：僅列審查中稿件，顯示作者、類別、標題及查看操作。
4. 稿件內容頁：顯示完整內容；編輯可通過或退回審查中稿件。

## 四、建議資料結構

### 使用者

- id：使用者唯一編號。
- name：姓名。
- role：作者或編輯。

### 稿件

- id：稿件唯一編號。
- author_id：對應作者編號。
- category：類別。
- title：標題。
- content：文章內容。
- status：編輯中、審查中或已通過。
- created_at：建立時間。
- updated_at：更新時間。

一位作者可擁有多篇稿件，每篇稿件對應一位作者。固定類別可先使用下拉選單，不另做類別管理。

## 五、尚待決定與延後功能

- 技術框架與資料儲存方式尚未指定。
- 登入未列在簡報中；若課程無額外要求，可先使用測試身分展示流程。測試身分切換僅適用於展示，不視為正式登入驗證。
- 搜尋、審查意見、通知、附件與類別管理可延後，不列入第一版核心範圍。
