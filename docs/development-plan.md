# 開發計畫

## 規劃假設

由一人製作，以七天完成核心系統與展示準備為目標。以下為相對日程，實際日期依正式期限調整。

## 七天時程

1. 第一天：確認需求、狀態規則與四個頁面草圖；確定技術框架。
2. 第二天：建立資料結構，準備作者、編輯與三種狀態的測試稿件。
3. 第三天：完成作者清單、新增、修改與刪除。
4. 第四天：完成送出、待審查清單、內容檢視、通過與退回。
5. 第五天：完成必填驗證、身分與狀態限制、確認及結果提示。
6. 第六天：執行驗收情境，修正資料更新與畫面問題。
7. 第七天：整理操作截圖、系統說明與展示資料，預留緩衝時間。

## 工作清單

- [ ] 確認技術框架與資料儲存方式。
- [ ] 完成資料結構與測試資料。
- [ ] 完成作者功能。
- [ ] 完成編輯功能。
- [ ] 完成狀態與權限限制。
- [ ] 通過驗收清單。
- [ ] 補上 README 的安裝與執行方法。
- [ ] 準備展示與操作說明。

## 建議交付內容

可執行系統、原始碼、測試資料及操作說明。此為建議清單，簡報未指定繳交格式。

## 展示腳本

1. 第一篇稿件示範新增、修改與刪除。
2. 第二篇稿件示範新增、送出、退回、修改、再送出與通過。
3. 在作者與編輯畫面間切換，說明同一篇稿件的狀態與可用操作如何變動。

## GitHub 維護建議

- 依資料結構、作者功能、編輯功能與驗收修正分階段提交。
- README 持續更新實作進度與執行方式。
- 不提交密碼、權杖、個人環境設定或真實使用者稿件。
